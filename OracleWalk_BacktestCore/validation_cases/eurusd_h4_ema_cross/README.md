# Validation case: EURUSD H4 — EMA Cross

Compares BacktestCore's `EmaCrossStrategy` against the MT5 Strategy Tester
running `ReferenceEmaCrossEA.mq5`, on the same EURUSD H4 broker package.

See `../../docs/mt5_validation.md` for the full runbook.

## Fixed inputs (must be identical on both sides)

| Parameter | Value |
| --- | --- |
| Symbol / Timeframe | EURUSD / H4 |
| Data | `data/broker_exports/FTMO Global Markets Ltd/EURUSD/H4` (5000 bars) |
| Range | 2023-03-16 → 2026-06-03 (per `export_manifest.json`) |
| FastPeriod / SlowPeriod | 12 / 36 |
| AtrPeriod | 14 |
| StopAtr / TakeAtr | 1.5 / 3.0 |
| Lots | 0.10 |
| CloseOnOpposite | true |
| Initial deposit | 10000 |
| Leverage | 1:30 |
| Commission | 0 on both sides (isolate) |
| MT5 modelling | Every tick based on real ticks |

## Files

| File | Source |
| --- | --- |
| `generate_backtestcore_trades.py` | committed — reproduces the BT side |
| `backtestcore_trades.csv` | generated by the script above |
| `backtestcore_run.json` | exact engine settings + summary used |
| `mt5_trades.csv` | **you produce this** from the EA in the Strategy Tester |

## BacktestCore result (already generated)

- Total trades: **150**
- Net PnL: **+37.87** (on 10000, ~3.2 years, 0.10 lot, commission 0)
- Exit reasons: `sl=87, tp=47, signal=15, eod=1`
- First entry: `2023-03-17 00:00:00` @ `1.06184`
- Last exit: `2026-06-03 12:00:00`

Regenerate any time:

```bash
.venv/bin/python validation_cases/eurusd_h4_ema_cross/generate_backtestcore_trades.py
```

## To complete the comparison

1. Run `ReferenceEmaCrossEA` in the MT5 Strategy Tester with the inputs above
   (start with `StopAtr=0, TakeAtr=0` to isolate timing, then 1.5/3.0).
2. Save the EA's CSV here as `mt5_trades.csv`.
3. Run:

   ```bash
   python ../../scripts/compare_mt5_trades.py \
     --mt5 mt5_trades.csv \
     --bt  backtestcore_trades.csv \
     --price-tol 0.00002 \
     --time-tol-seconds 5 \
     --out comparison.json
   ```

## Comparator self-test (already verified)

The comparator was checked by feeding the BacktestCore trades back in under the
MT5 schema: **150/150 paired, max|Δ| = 0** on entry price, exit price and PnL.
So a non-zero divergence against real MT5 output reflects genuine engine/
execution differences, not a tooling artefact.

## Expected divergences

Per `docs/mt5_validation.md`: fill timing (BT close-of-signal-bar vs MT5
next-bar open), bid/ask spread, intrabar SL/TP ordering (BT assumes SL first),
and commission/swap settings. With 87 of 150 BT exits being stop-losses, the
**intrabar SL-vs-TP ordering** is the divergence most likely to show up here —
which is exactly what running MT5 in real-tick mode is meant to test.
